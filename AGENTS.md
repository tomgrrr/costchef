# CostChef

Ruby on Rails SaaS for catering businesses: calculates recipe material costs (replaces Excel).
**Multi-tenant: every user owns and sees only their own data.**

**Stack:** Rails 7.1.6 · Ruby 3.3.5 · PostgreSQL · Bootstrap 5 · Stimulus/Turbo (Hotwire)

## Commands
```bash
bin/dev                   # dev server (web + CSS watcher via foreman)
bin/setup                 # set up environment
bin/rails db:prepare      # create + migrate
bin/rails db:migrate      # run migrations
bin/rails db:seed         # load seed data
bundle exec rspec         # test suite (593 specs)
rubocop -a                # lint + auto-fix
yarn build:css            # one-off CSS build
bin/rails console         # console
```

## Boundaries
- 🚫 **Never commit secrets.** Config comes from ENV only (see `.env.example`).
- 🚫 **Never let a query cross users.** Every read/write is scoped to the current user —
  tenant isolation is the #1 invariant, and `spec/requests/**` assert it. Keep them green.
- 🚫 **No business logic in ActiveRecord callbacks.** All calculations go through Services.
  Only allowed callbacks: `ProductPurchase#before_validation` (PricePerKg) and
  `Product#before_validation` (clears rehydration coefficient when unchecked).
- 🚫 **Don't hand-edit `db/schema.rb`** — it's generated by migrations.
- ⚠️ **Ask before** running a migration on shared data, or changing anything under
  `config/initializers/` (auth, CSP, Rack::Attack, subscription gate).

## Architecture (overview)
- **Models** — data + validations only, no business logic.
- **Services** (`app/services/{domain}/{action}.rb`, called `Domain::ActionName.call(obj)`) —
  every calculation and the recalculation cascade.
- **Controllers** — thin; `authenticate_user!` + `ensure_subscription!` + Pagy pagination;
  Turbo Streams for dynamic updates.
- **Frontend** — ERB + Bootstrap 5, Stimulus controllers, custom design system.

## Code rules
- Max 10 lines per method — decompose into private sub-methods.
- One service = one action (SRP). Validate inputs at service entry, fail fast with explicit errors.
- Services don't persist, except `*Recalculator` / `AvgPriceRecalculator` (via `update_columns`).
- Test every service with a dedicated RSpec before wiring it into a controller.

## Data model (invariants that aren't obvious from the code)
- **User** — owns everything. `markup_coefficient` (≥0.1, default 1.0),
  `price_variability_threshold` (0–100, CV% alert). Devise `:lockable` + `:timeoutable`.
- **Product** — ingredient library. `base_unit ∈ [kg, l, piece]`; if `piece`, `unit_weight_kg`
  required (>0), otherwise absent. `dehydrated` (kg only) requires `rehydration_coefficient > 1`.
  `high_variability?` = CV% above the user's threshold.
- **ProductPurchase** — price history. `package_unit` must match the product's `base_unit`
  (`Units.allowed_for`). `package_quantity_kg` + `price_per_kg` computed by `PricePerKgCalculator`.
  `active` filters obsolete prices.
- **Recipe** — 4 cached metrics (`cached_total_cost/total_weight/cost_per_kg/raw_weight`).
  `cooking_loss_percentage` (0–100). `sellable_as_component` gates sub-recipe use.
  `sold_by_unit` requires `unit_reference_weight_kg > 0`.
- **RecipeComponent** — polymorphic (Product | Recipe). **Max 3 levels of sub-recipe depth.**
  No self/circular reference. `effective_weight_kg` applies rehydration; **`line_cost` always
  uses dry `quantity_kg`** — cost is unaffected by rehydration.
- **Supplier** — soft-delete via `active`; `force_destroy!` (raw SQL) returns impacted
  `product_ids` for the Dispatcher.
- **TraySize** — optional; `before_destroy` nullifies recipes' `tray_size_id`.
- **DailySpecial** — independent history; categories meat/fish/side + averages.
- **Invitation** — invitation-only signup; auto `token`, 7-day expiry.

Relationships: User `has_many` Products/Recipes/Suppliers/TraySizes/DailySpecials (cascade),
Invitations (nullify). Product → ProductPurchases (cascade), RecipeComponents (restrict).
Unique index `[user_id, name]` on Product.

## Services & calculation cascade
- **`Units` / `Units::Converter`** — single source of truth for unit conversion
  (kg identity, g÷1000, l=1kg, cl÷100, ml÷1000, piece×`unit_weight_kg`; 0.0 if piece weight missing).
- **`ProductPurchases::PricePerKgCalculator`** — derives `package_quantity_kg` + `price_per_kg` (no persist).
- **`Products::VariabilityCalculator`** — CV% of active purchases (population stddev; nil if <2 or mean ≤0).
- **`Products::AvgPriceRecalculator`** — weighted avg `SUM(qty×price)/SUM(qty)`; persists; raises if nil/negative.
- **`Recipes::Recalculator`** — recomputes the 4 `cached_*` (raw weight uses rehydrated weight,
  cost uses dry weight); persists; does NOT cascade to parents.
- **`Recipes::Duplicator`** — shallow copy, returns unsaved object.
- **`Recalculations::Dispatcher`** — orchestrates the cascade up to parent recipes (max 3 levels):
  `product_purchase_changed`, `recipe_component_changed`, `recipe_changed`,
  `supplier_force_destroyed`, `full_product_recalculation`.

## Controllers (map — all scoped to current_user, Pagy on index, default 50)
- **Products** — search (ILIKE), CSV export (semicolon), blocks delete if used in a recipe,
  triggers `Dispatcher.full_product_recalculation` on dehydrated/coefficient change.
- **Recipes** — tabs (recipes/subrecipes), CSV + Excel export (caxlsx), demotion alert,
  `sold_by_unit` g→kg conversion.
- **Suppliers** — soft-delete + force destroy with cascade recalc.
- **ProductPurchases / RecipeComponents** — Turbo Streams, trigger the Dispatcher.
- **StandardDeviations** — CV% index (`pagy_array`). **Settings** — markup + variability threshold.
- **Admin::*** — `require_admin!`, skips `ensure_subscription!`.

## Auth & access
- Devise, invitation-only signup (registration route skipped), min 8-char password,
  `:lockable` (5 attempts / 1h), `:timeoutable` (30 min).
- Rack::Attack throttling (login 5/min, signup 3/min, resets 5/min), French 429.
- Strict CSP (fonts from Google, icons bundled locally). `ensure_subscription!` gate in
  `ApplicationController`; `/admin` behind `require_admin!`.

## Testing
593 specs, run with `bundle exec rspec`. Conventions:
- Request specs: `sign_in user`, `before(:each)` only (no `before(:all)`).
- Use `let!` for the invitation in POST specs asserting `change(User, :count)` (the invitation
  factory creates an admin user).
- Product name is unique per user — use distinct names, not `create_list`.
- Layout: `spec/services/`, `spec/models/`, `spec/requests/`, and
  `spec/deployment/pre_deploy_spec.rb` (secrets/gitignore/schema/CSP/Docker checks).
